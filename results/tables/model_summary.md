## Key idea

| Model | Key idea |
|---|---|
| MLP | Flatten the image, stack fully-connected layers. |
| Simple CNN | Small 3x3 convolutions, pool, repeat. Weights shared across positions. |
| ResNet-18 | Residual connections let gradients skip layers, making depth trainable. |
| ViT | Patch the image into tokens; every token attends to every other. |
| MLP-Mixer | Alternate token-mixing and channel-mixing MLPs; no attention at all. |
| ConvNeXt-mini | A ConvNet with Transformer design choices: 7x7 depthwise, LN, GELU, inverted bottleneck. |

## Overfit test (spec 5.7)

Can each model memorise 256 training images in 200 optimizer steps? This is a wiring-and-capacity check, so it runs
without augmentation, weight decay, label smoothing, dropout or stochastic depth --
all five exist to *prevent* a model fitting its training data, which is exactly what is
being measured here. The LR schedule is linear warmup then cosine decay, matching the
protocol (spec Section 3). Accuracy is measured in `eval()` mode.

> **Why the schedule matters.** ViT initially failed this gate at 82%. Three things were
> wrong with the *test*, not the model: stochastic depth was left on (+7.5pp when
> disabled), there was no LR warmup (+7.8pp), and the post-warmup LR was held constant
> rather than decayed. That last one was visible in the loss curve -- ViT reached a loss
> of 0.119 by step 150 and then bounced back to 0.406 by step 199, the signature of a
> learning rate too large to settle into a minimum it had already found. With cosine
> decay it reaches 100%. No model hyperparameter was changed to achieve this.
